# CLAUDE.md — Flutter app

Applies to all code in `app/`. The rules in `/CLAUDE.md` still apply.

## Role of the app

The Flutter app handles **only** rendering, input, navigation, and UI state.
All data is read and changed through the Rust API (`lib/src/rust/`, generated by flutter_rust_bridge).
If a feature needs logic (database filters, merging, encryption, search), add it in Rust (`crates/ffi/src/api/`), not in Dart.

## Structure

```
lib/
├── main.dart              # init RustLib, ProviderScope
├── app.dart               # MaterialApp.router, theme, l10n
├── src/rust/              # GENERATED — do not edit
├── core/
│   ├── providers/         # providers wrapping the Rust API
│   ├── router/            # go_router route definitions
│   ├── theme/
│   └── utils/
└── features/<feature>/
    ├── presentation/      # screens & widgets
    ├── application/       # Riverpod Notifier/AsyncNotifier
    └── widgets/           # small feature-specific widgets
```

Planned features: `onboarding`, `workspace`, `editor`, `database`, `search`, `devices`, `backup`, `settings`.

## Rust initialization

```dart
Future<void> main() async {
  WidgetsFlutterBinding.ensureInitialized();
  await RustLib.init();
  runApp(const ProviderScope(child: NoteSyncApp()));
}
```

## State management (Riverpod)

- Use Riverpod with code generation (`@riverpod`).
- Rust API calls are wrapped in providers in `core/providers/` or `features/<feature>/application/`. Widgets never call the Rust API directly.
- Streams from Rust (sync status, document changes) are exposed as `StreamProvider`s.
- Errors from Rust are shown via `AsyncValue.error` using an l10n message chosen by `code`, never the raw message.

## Editor

- The editor uses `appflowy_editor`.
- An adapter in `features/editor/` translates editor transactions into operations sent to Rust (`apply_block_ops`), and applies changes from Rust (`DocChanged` events) back to the editor.
- Avoid loops: changes that came from Rust must never be sent back to Rust. Tag every operation with its origin (`origin: local | remote`).
- Operation format: see `docs/data-model.md` §4.

## Platforms

| Platform | Notes |
|---|---|
| Web | No mDNS/QUIC. Sync via WebRTC + relay. SQLite WASM storage in OPFS. |
| iOS | Sync only while the app is active. Requires Local Network permission (`Info.plist`). |
| Android | Needs a multicast lock for mDNS (handled in Rust/plugin); permissions in `AndroidManifest.xml`. |
| Desktop | Full feature set. |

Platform checks in Dart are fine for UI concerns (e.g. hiding the QR scan button on desktops without a camera). Transport selection happens in Rust.

## UI & accessibility

- All UI text comes from `AppLocalizations` (`l10n/app_en.arb`, `l10n/app_id.arb`). Add every new key to both files.
- Support light and dark themes.
- Responsive layout: mobile (bottom nav / drawer); desktop & web (persistent sidebar).
- Interactive widgets need clear `Semantics` / tooltips.

## Testing

- Widget tests for every main screen in `test/features/<feature>/`.
- Override providers with a fake API in tests; never call real Rust in widget tests.
- `integration_test/` for end-to-end flows (create account → create page → edit → search).
